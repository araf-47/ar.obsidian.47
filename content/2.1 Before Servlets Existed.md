# 2.1 Before Servlets Existed

Let's travel back to the late 1990s.

There was no:

* Spring Boot
* Spring MVC
* JSP (initially)
* Thymeleaf
* React
* Angular

A browser requested a webpage.

Someone had to generate HTML.

Who?

---

Suppose Firefox sends:

```http
GET /students HTTP/1.1
```

Tomcat receives it.

Now Tomcat needs **Java code** that says:

> "When someone asks for `/students`, generate an HTML page."

That Java code is called a **Servlet**.

---

# So What Is a Servlet?

Let's build the definition instead of memorizing one.

Imagine this Java program:

```java
public class Calculator {

    public int add(int a, int b) {
        return a + b;
    }

}
```

This is an ordinary Java class.

It doesn't know anything about:

* Browsers
* HTTP
* Tomcat

It just performs calculations.

Now imagine another Java class.

Instead of adding numbers...

It receives HTTP requests.

That's a Servlet.

---

## Definition

A **Servlet** is a **special Java class** that is designed to handle HTTP requests and generate HTTP responses.

Notice the important words:

* Java class ✅
* HTTP request ✅
* HTTP response ✅

Nothing magical yet.

---

# But Wait...

If it's "just a Java class"...

Can we do this?

```java
public static void main(String[] args)
```

No.

Why?

Because **you don't run Servlets.**

Tomcat runs them.

This is the first big idea.

---

# Normal Java Program

```text
You

↓

java Hello
```

You are in control.

---

# Servlet

```text
Browser

↓

Tomcat

↓

Servlet
```

Tomcat is in control.

This is called **Inversion of Control (IoC).**

Don't worry about the name now.

Just remember:

> **You don't call the Servlet. Tomcat calls the Servlet.**

That idea will appear again in Spring Boot.

---

# What Does a Servlet Actually Look Like?

Don't memorize this yet.

Just observe it.

```java
import jakarta.servlet.http.HttpServlet;

public class StudentServlet extends HttpServlet {

}
```

Notice something strange.

Our class is extending another class.

```java
extends HttpServlet
```

Why?

Because `HttpServlet` already knows how to work with HTTP.

We're simply customizing it.

Think of it like inheriting from a base class that already understands web requests.

---

# The Important Relationship

```
Object
   ↑
GenericServlet
   ↑
HttpServlet
   ↑
StudentServlet
```

Don't panic.

You already know inheritance from Java.

This is simply inheritance being used in web development.

---

# Why Doesn't Tomcat Accept Any Java Class?

Suppose you write:

```java
public class Cat {

}
```

Can Tomcat use it as a Servlet?

No.

Why?

Because Tomcat expects a class that follows the Servlet contract.

When your class extends `HttpServlet`, you're telling Tomcat:

> "This class knows how to behave like a Servlet."

It's similar to how a class implementing an interface promises to provide certain behavior.

---

# The Servlet's Job

A Servlet has one job:

```
Receive Request

↓

Do Some Work

↓

Send Response
```

That's all.

The work might be:

* Read from SQLite
* Calculate something
* Validate a login
* Save a student

Then return a response.

---

# Example

Browser asks:

```
GET /time
```

Servlet calculates:

```
Current Time

↓

8:35 PM
```

Generates:

```html
<h1>Current Time</h1>

<p>8:35 PM</p>
```

Tomcat sends it back.

---

# Why JSP Was Invented

Suppose your Servlet generates HTML like this:

```java
out.println("<html>");
out.println("<body>");
out.println("<h1>Students</h1>");
out.println("<table>");
out.println("<tr>");
out.println("<td>Alice</td>");
out.println("</tr>");
out.println("</table>");
out.println("</body>");
out.println("</html>");
```

Imagine writing an entire Bootstrap website like this.

Hundreds of `out.println()` calls.

Would you enjoy maintaining that?

Probably not.

Developers felt the same way.

So JSP was invented.

Instead of:

> Java containing HTML

JSP became:

> HTML containing small pieces of Java.

That made web pages much easier to read and maintain.

---

# The Bridge to JSP

This is the key idea of the whole module.

```
Servlet

↓

Generates HTML
```

Later you'll learn:

```
JSP

↓

Tomcat automatically converts it

↓

Servlet

↓

Generates HTML
```

This is why **we're learning Servlets first**.

A JSP is **not an alternative technology**.

A JSP eventually becomes a Servlet.

If you understand a Servlet, you'll understand what's happening behind every JSP page.

# ⭐ One Important Idea

I want to plant a seed now because it'll help you later.

You currently think:

> Browser → Tomcat → Servlet → HTML

That's correct.

But later you'll learn the **Servlet doesn't actually "display" HTML**.

Instead, it writes HTML into the **HTTP response**.

Something like this:

```java
PrintWriter out = response.getWriter();

out.println("<h1>Hello</h1>");
```

That HTML is placed inside the response body.

Tomcat then packages it into a proper HTTP response and sends it to the browser.

We'll see this in action soon.
